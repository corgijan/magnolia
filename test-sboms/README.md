# Real-world SBOM test fixtures

Every file here was generated by [`syft`](https://github.com/anchore/syft)
(Anchore's SBOM generator, the same tool many real users point at Magnolia)
against this repo's own real dependency manifests — genuine component
graphs, purls, and license data, not hand-crafted fixtures. They're used by
`tests/test_real_sboms.py` and by `crates/core/src/schema_validation.rs`'s
own unit tests.

| File | Source | Ecosystem(s) | Format | Components |
|---|---|---|---|---|
| `repo-mixed.cdx16.json` | this repo (root, excluding `target/`/`node_modules/`) | Cargo + npm | CycloneDX 1.6 | ~1600 |
| `frontend-npm.cdx15.json` | `frontend/` (`package-lock.json`) | npm | CycloneDX 1.5 | ~1285 |
| `frontend-npm.spdx23.json` | `frontend/` (`package-lock.json`) | npm | SPDX 2.3 | ~1268 |
| `rust-workspace.spdx22.json` | `Cargo.lock` | Cargo | SPDX 2.2 | ~367 |

Deliberately spans every CycloneDX (1.4/1.5/1.6) and SPDX (2.2/2.3) version
`validate_sbom_schema` claims to support (see
`crates/core/src/schema_validation.rs`), plus both single- and
mixed-ecosystem component graphs.

## Regenerating

```bash
syft scan dir:. --exclude './target/**' --exclude './frontend/node_modules/**' --exclude './.git/**' --exclude './.aidex/**' \
  -o "cyclonedx-json@1.6=test-sboms/repo-mixed.cdx16.json"

syft scan dir:./frontend --exclude './frontend/node_modules/**' \
  -o "cyclonedx-json@1.5=test-sboms/frontend-npm.cdx15.json"

syft scan dir:./frontend --exclude './frontend/node_modules/**' \
  -o "spdx-json@2.3=test-sboms/frontend-npm.spdx23.json"

syft scan file:./Cargo.lock \
  -o "spdx-json@2.2=test-sboms/rust-workspace.spdx22.json"
```

Regenerate after a significant `Cargo.lock`/`frontend/package-lock.json`
change if you want the fixtures to track current reality — not required
for the test suites to keep passing, since they only assert properties
that should hold for *any* valid real-world SBOM.
